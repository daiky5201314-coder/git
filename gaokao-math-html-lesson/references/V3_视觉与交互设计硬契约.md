# V3 阻断性标准：必须做成「完整交互教学课」，而不是「3D 图 + 一句话提示」

> **此文件是 V3 的视觉/教学最高执行标准。** 受认可的主参考：`../examples/首选视觉交互参考_2025第17题.html` 和 `../assets/首选视觉基准_第17题_证明步骤.png`。请亲自打开演示并操作至少一分钟，而不是仅看源码。
>
> 每次新题仍从零完成知识、推导和数学模型；主参考提供的是**交互逻辑、信息层级、授课节奏和画面关系**，不是照搬一道旧题的数据。

## 1. 用户认可的呈现模式

桌面采用连续的四区域体系，手机纵向重排：

```text
┌────────────────────── 顶部：年份/卷名/题号/完整原题入口 ──────────────────────┐
│  ┌──────────────── 数学主舞台（左 60~67%） ──────────┐ ┌─ 教学导航（右） ─┐ │
│  │ 本幕目标 / 3D场景或函数动画 / 关键对象标签 / 图例     │ │ 题意 知识 思路  │ │
│  │ 画面聚焦当前数学关系；前置对象可淡化                │ │ 解题1 解题2 巩固 │ │
│  └────────────────────────────────────────────────┘ ├─ 当前教学卡片 ─┤ │
│  ┌──────────── 播放／暂停／上下步／进度／速度 ─────────┐ │ 目标+为何这样做   │ │
│  │ seek 与时间、公式、图形同源；点击数字步骤能定位       │ │ 分行推导+结论    │ │
│  └────────────────────────────────────────────────┘ │ 预测/提示/反馈   │ │
│                                                       └──────────────────┘ │
└─────────────────────────────────────────────────────────────────────────────┘
```

- **主舞台必须是视线中心**：动态数学对象宽度合理，模型自动适应视图；点线面、函数、切线/法向量、结论高亮标签有稳定颜色和层次。舞台本身必须显示当前的数学问题或观察提示。
- **教学导航必须在首屏直接可见**：题目理解／基础知识／解题思路／第(1)问／第(2)问／总结等（按实际题目增减），已完成、正在学习、未学习三态明显；点击导航可以跳到对应章节，不只是纯文本目录。
- **右侧教学卡片必须是完整微步骤**：醒目的步号/教学目标；一两句“为什么”；可阅读的关键条件或推导；当前结论；必要的交互提问。不能只放 `caption + 一个公式`，更不能要求学生往下找隐藏的完整证明。
- **底部播放区**：始终可操作，控制与进度/步骤同源；暂停/继续、重播、上一/下一、时间条、倍速；另有数学探索操作（拖角度、切换辅助面、拖参数/切线）。
- **完整原题**：有不被截断的阅读入口（如顶部“完整原题”按钮），核心条件在第一模块逐一展示；不能只在折叠栏里写一次题目。

## 2. 教学顺序不是一级目录列表，而是镜头内的知识建构

每个必要知识点应按以下次序可**单独学习**：

1. **为何需要**：把当前解题目标与陌生知识连接起来，解释学它能解决什么困难。例如“我们想从两条垂直关系推到直线垂直一个面”。
2. **直观试验**：在**真实数学模型或单独的入门例子**中，图形发生可观察的变化（线画出来、切线沿曲线移动、垂面展开、角从两个方向逐渐张开）；允许暂停或拖动探索。
3. **概念/定义**：指出可视对象的数学名称、必要条件、符号，不把猜想当定理。
4. **定理与适用条件**：把每个前提逐项高亮，重要限制和易错点以不同视觉语言呈现。
5. **迁移到本题**：回到题设图，连接前提→数学操作→本题当前结论。不同题不许直接套旧题的坐标/函数。
6. **一分钟理解检验**：学生可预测下一步、显示提示、看解释；回答反馈应解释原因，而不只显示“正确”。

**知识点的动效与本题证明不能强行混成一帧**。先用简单例子理解原理，再回到高考题应用；已经懂的学生可以点击导航跳过。不要让学生为了看知识点先阅读一屏满满的长段文字。

## 3. 单个教学步骤内容语法（强制）

每个重要步骤必须拥有可见的 6 个信息层（可以随播放次序渐显，但绝不只剩第一层）：

- **当前目标**：要证明/求什么？（一句）
- **思考原因**：为什么尝试这个工具或构造？（自然语言，明确数学因果）
- **动画动作**：哪一条线/哪一个面/哪一段函数真正动？由什么数学量驱动？
- **推导过程**：必要公式分行、按条件推进；解释每个等号/推理的依据。
- **阶段结论**：本步证明了什么，如何推进下一步？
- **参与互动**：关键点预测/提示/自测，按题型合理设置，不必每一秒强迫点按钮。

**正确节奏**：`提出问题 → 先让学生观察/预测 → 演示数学变化 → 解释定义/推理依据 → 逐步出现公式 → 得出结论 → 进入下一步`。

**禁止反模式**：
- 先弹出最终公式，然后在右侧只写两行概述；完整证明藏在下方 `<details>` 里。
- 只显示整页“知识点清单+公式”而没有真正对应的动画。
- 一段文字自动轮播，模型只偶尔闪一下；假“自动演示”。
- 所有文字都用同一种字体、卡片、一段话，学生分不清观察、想法、严格推导和结论。
- 场景空旷、模型过小、标签压线、平面无深度区分；自动镜头没有针对当前步骤取景。

## 4. 题型决定动画，但交互逻辑一致

**函数**：知识教学从直观移动点/变化率开始；坐标轴先出现，曲线逐点生长，运动点与 `x,f(x),f'(x)` 同步，极值/零点处聚焦；右卡同步显示“看到了什么、怎样用导数严格证明”；比较题突出对称点/差函数与所求结论对应。函数推导不能只是最后展示正确结果。

**立体几何**：知识教学展示“直线与面”的三维关系，辅助手段有明确出现顺序；镜头在最佳角度展示垂直、平行、投影和法向量；向量法的每个坐标均有来源说明。空间对象真实 3D、旋转可拖拽，透明辅助面、遮挡和必要图例清楚。

**概率/数列/解析几何**：换对应数学画面，**不要复制第 17 题的 3D 平面画法**；保留教学导航、微步骤卡、参与思考和自动动画的协作逻辑。

## 5. 交互优先级

- 初学者：点一次“▶ 自动演示”连续观看，图形/推导同步；不需逐页点击，也不会忽略知识点。
- 自主探索：可以暂停，拖动图形或参数，显示/隐藏辅助元素；数学数据立即同步。
- 快速复习：可直接点击某知识点/步骤数字跳转，一次看到该步图、式、原因与结论。
- 学生思考：预测可在关键帧暂停或选择先看提示；猜错要有带数学依据的反馈。
- 所有互动不能破坏状态一致性；进度条拖动后，导航状态、教学卡片与数学舞台须一起还原。

## 6. 视觉细节与移动端

- 主舞台用暗色教学画布、教学侧栏用亮色背景，形成明确主次；避免花哨渐变遮挡数学。
- 主要曲线/图形蓝绿、辅助对象紫、当前观察橙、结论绿、错误灰红，且搭配标签/线型。
- 标题、当前目标、推导公式必须可读；数学表达优先清晰的多行排式；不允许原始 HTML 字符或 Unicode 向量混排导致公式难读。
- 首屏避免超过两屏滚动才能到“当前完整推导”；屏幕小则舞台→进度操作→教学卡纵向，重要按钮可以触达。
- 当学生跳到后半章节，图像/步骤必须一致，不能出现“一个章节标题+旧章节的图”。

## 7. 可执行 UI 语义（V3 新题必须具备）

这些标记不改变页面美观，供浏览器自动检查逻辑结构；旧版视觉成品不必满足 V3 标记：

```html
<main data-lesson-region="layout">
  <section data-lesson-region="stage" aria-label="数学演示区"><canvas>...</canvas></section>
  <aside data-lesson-region="teaching-side">
    <nav data-lesson-region="chapter-nav" aria-label="教学章节"></nav>
    <section data-lesson-region="teaching-card">
      <h2 data-lesson-role="step-title">本步标题</h2>
      <p data-lesson-role="objective">本步目标</p>
      <p data-lesson-role="why">为什么这样做</p>
      <div data-lesson-role="derivation">完整的本步推导</div>
      <div data-lesson-role="conclusion">本步结论</div>
      <div data-lesson-role="reflection">预测/提示/互动内容</div>
    </section>
  </aside>
</main>
<div data-lesson-region="controls">播放、暂停、步进、进度、速度</div>
```

- 各区块内容由共享 `sceneAt(t,params)` 的当前教学步骤对象决定；隐藏某个字段应是**教学原因**（如正在观察，还没推导），不能永远不给出推导。
- 切换章节时 `step-title/objective/why/derivation/conclusion/reflection` 中对应内容自动更新；测试会在中段逐个检查。
- 章节按钮要有真实 `data-lesson-chapter="id"` 标记，点击定位，活动状态用 `aria-current="step"` 或等价标记；不是静态装饰。

## 8. 什么样的作品才算 V3 合格

通过 V2 的工程与数学测试只是必要条件；另外必须：

1. 浏览器桌面 1440×900 和手机 390×844 截图对比首选视觉基准，主舞台有数学主体、右侧有完整教学卡片，字号及比例符合当前题型。
2. 实际播放并截图检查至少**知识点引入 → 知识点动态例子 → 迁移到本题 → 严格推导 → 结论**五种教学状态。
3. 检查**思考原因**而非只有公式；知识点定义、示例、定理使用条件在可见的教学流程中出现。
4. 检查学生不用展开任何隐藏区也能看完整的关键解题步骤。
5. 运行 `scripts/visual_teaching_contract_test.py 目标文件.html --shots 截图文件夹`；运行 V2 原有静态与浏览器测试。
6. 人工判定镜头景别、文字和几何遮挡；如果数学内容很长，需要按可理解的小步拆分，不能靠缩小字体容纳。

**只要页面技术合格但教学画面/逻辑不符，本题仍判定“不合格”，必须重做。**
