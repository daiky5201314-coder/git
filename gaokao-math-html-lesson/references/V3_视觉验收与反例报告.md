# V3 视觉验收：好成品与不合格页面的可操作比较

## 必看三张截图

- `../assets/首选视觉基准_第17题_证明步骤.png`：正例。主舞台形状够大，右侧有步骤号、推导过程、结论、思考互动、章导航，下方有播放和进度。
- `../assets/首选视觉基准_第17题_手机.png`：正例移动端布局。
- `../assets/反面案例_第16题_图文脱节.png`：反例。舞台大面积空白，模型偏小；右侧卡只有少量文字和单行结论；完整证明放在折叠区，学生不展开看不到；标签重叠。

## 必须逐项签字验收

| 项目 | 正例应有 | 反例迹象 | 修复策略 |
|---|---|---|---|
| 视觉聚焦 | 画面主体居中且占可视区合适比例 | 图形缩在一角，周围大片空 | 镜头自动适配关键对象包围盒 |
| 章节导航 | 题意/知识/思路/分问/巩固有点击跳转 | 仅写模块 ABC 或没有导航 | 设置真实导航按钮，时间和样式联动 |
| 当前步骤 | 步号、目标、原因、分行推导、结论 | 只有一句 caption 和一个 formula | 采用六层教学卡片，可按时间渐显 |
| 知识教学 | 有简单动态示例和条件核验 | 教科书式静态定理 | 单独小动画→本题迁移 |
| 演示动作 | 数学对象真实形成、移动、变形 | 整个图形突然出现/变色 | 数学参数连续插值或逐段绘制 |
| 学生参与 | 预测、提示、反馈紧贴当前问题 | 仅结束时三道选择题 | 思考框嵌入相关证明节点 |
| 证明完整性 | 本步完整推导能在右侧看到 | 完整证明全部藏下方 | 移到步骤卡，完整答案仅供复读 |
| 同步 | 文字、镜头、标注、公式与进度同步 | 上一步文字还停留着 | 统一 `sceneAt(t)` 数据源 |
| 字体/数学 | 公式结构清晰，长推导分行 | 字符堆砌、标记干扰、挤成一行 | 数学排版结构、足够行高 |
| 手机端 | 视频舞台与步骤卡上下排列 | 按钮挤成行/卡片溢出 | 竖排控件、水平可滚动章节导航 |

## 测试方式（缺一不可）

1. 先运行 V2 工程合同测试和数学独立核验。
2. 运行 `scripts/visual_teaching_contract_test.py 成品.html --shots ./visualQA/`，拿到截图和结构报告。
3. **真人对照三张基准图片**，观看知识点引入、独立示例、应用本题、证明、结论 5 个节点的视频/画面；每一帧按表格逐项判定，不合格重做。
4. 试着不展开 `<details>` 完成两问的学习；若不行则失败。
5. 重点检验教学是否解释“为什么想到这种解法”，而非只是把正确答案读出来。

## 自动化能力边界

脚本能拦截缺导航、缺卡片、无右侧推导、移动端明显溢出等工程问题，但**不能自动判断数学动画是否真的帮助理解、镜头是否美观、颜色是否对比足够**。这些必须通过截图和实际观看人工确认。不得把通过自动脚本等同于“教学质量和视觉效果已完全合格”。
