# 不合格案例：2026 云南第16题 AI 生成 HTML——防复发审查清单

背景：另一 Agent 生成的 HTML 存在实际行为缺陷；参考其**错误模式**，不得照搬其工程实现。这里不将它作为原题或正确实现的依据。

| 错误行为 | 根因示例 | 必须采用的修复方式 | 自动验收 |
|---|---|---|---|
| 第2章起正文多次不更新 | PANEL 使用跨章全局 `at`（15.5 等），而面板挑选用章节局部 `chT`（0 到该章长度） | 所有事件时间统一全局；或在章节内只用局部秒数并仅比较局部事件；对比两个以上章节的子句变更 | 检查中段章节内 `captionId` 随进度改变 |
| 线看似需要慢慢长出，却一瞬间整条出现 | 建立 `p` 字段，但画线 `line2(project(a),project(b))` 没有使用 `p` | 实际计算 `end=A+(B-A)*p` 再投影/描画 | 在生长期 20%/60%/100% 的 `sceneSignature` 不同 + 真实截图 |
| 播放进度条停在起点 | 只有 seekTo 触发 updateSeek，播放循环不更新 range.value | 所有 DOM 控件由统一 `applyTime` 同步 | 播放 0.8s 后进度条 value 必须上升 |
| 画面线条和半透明面空间层次失真 | Canvas 2D 顺序叠绘，未严谨考虑相交面/线的遮挡 | 提供深度测试或可说明的几何遮挡策略；复杂模型用 WebGL | 人工检查旋转到背面、面相交时的遮挡 |
| 动画与公式只粗略对应 | 一幕内长段文字 + 集体出现线/面/矢量 | 将数学操作拆为持续变化，公式/镜头/几何共用一条事件时间线 | 中间关键帧截图与内容比对 |
| 页面错位或放大后文字难读 | DPR/canvas 内部像素与 CSS 尺寸混用，标签未避让 | DPR 统一 CSS 坐标绘图；断点响应布局；对关键标注做避让 | 桌面/手机截图人工抽查 |

## 拒收条件

- 完全不具有中间态的「出现/消失」不能作为复杂几何操作的主要动画。
- 面板虽然有很多解释，但每章只停留第一句：直接拒收。
- 进度条不随播放头前进：直接拒收。
- 只做了 HTML 语法检查，没有浏览器互动测试：不得称「已验收」。
- 仅有标准答案和漂亮线条，缺少定理前提、推导依据及为什么选择方法：直接拒收。

## 生成前必须自行问答

1. 以任意 `t` 调 `sceneAt(t)` 两次，场景会完全相同吗？
2. 在任意分段中点 seek，文字、公式和图像都处于该段中间态吗？
3. 播放第 3 章时，子步骤是否真实变化，还是一直显示该章第一句？
4. 线生长的控制值参与最终画线了吗？
5. 点、线、面/曲线的实际数学坐标有独立校验吗？
6. 手机、断网以及性能弱的设备是否至少做了尽可能接近的浏览器测试？

## 完工报告模板

必须逐项报告：静态预检；Chrome/Chromium 播放；进度条；暂停/继续；seek 同态；章节内部字幕；真实生长中间态；3D 旋转/缩放（如适用）；移动端；网络断开；数学结论。每项写「通过 / 未通过 / 未测试」，不得将未测试写成通过。
